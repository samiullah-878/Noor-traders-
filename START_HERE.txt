DAILY HISAB
Sale + Wasooli + Kal ka Change - Akhrajat - Party payments - Aaj ka Change - Closing Cash = Farq.
Aaj ka counted Change next calendar day ki opening hai. Closing Cash carry forward nahi hoti.
Pichhle din ka record na ho to opening Change manually dein. Purani closing edit
karne se uske agle din ka opening/farq bhi update hoga.
Closing Cash screen mein har date ki cash ginti alag hai, cumulative balance nahi.
Wasooli aur payments party aur daily report mein ek entry se update hote hain.
Udhar diya / hum ne dena hai balance-only entries hain; daily cash mein shamil nahi.
Akhrajat mein kharcha account banayein, select karein, raqam save karein.

PDF IMPORT
Owner > PDF Import. Apni original All Parties List PDF select karein.
You'll Give = HUM NE LENE HAIN. You'll Get = HUM NE DENE HAIN.
Supplied All Parties report format was tested against every name and both totals.
Preview check karein, report ki tareekh set karein, Confirm Import dabayein.

this version does not replace their balances. Opening balance daily sale/expense nahi hai.
Original PDF saved in cloud with imported accounts; Settings > Saved PDF reports.
Private PDF / party data ZIP mein bundled nahi: public repository mein PDF upload na karein.

SYNC / OFFLINE
First login and first load internet par karein. Website aur SDK cache hone ke baad
existing cached session/data offline available ho sakti hai. New entries queue for sync.
Login verification, edits, closing, PDF import and restore require internet.
Cloud synced / cached / pending status ko dekhein. Pending entries device clear karne se kho sakti hain.
Offline clients can't verify account revocation until reconnecting.
Data same Firebase project ke separate blueKhata collection mein hai.
Sync button login se pehle app version checks; login ke baad pending data sync bhi waits.
New app update ke liye future ZIP same repository/path par replace karein. version.json
and sw.js cache version future release mein update honge. Login data is not in the public repo.

BACKUP
Settings > Backup download. JSON includes accounts/entries/closings and stored PDF chunks.
Restore owner-only online in batches. Matching records are skipped; conflicting
records block further restore without overwriting. If a batch fails, earlier restored
records remain; retry the same backup to resume.
Browser storage is not a replacement for backups. This build is not an Android APK.

VALIDATION
Arithmetic/unit checks; PDF names/details and both totals compared against extracted
source; DOM interaction tests use synthetic data. No production accounting records
were imported or modified while building. Firebase Rules and real mobile print/offline
behavior need deployment checks on your website. WebMCP browser validation unavailable.
